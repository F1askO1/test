Нативная iOS-сборка и фоновая запись на устройстве не проверены.** До этих внешних проверок полная приёмка этапа не завершена.

Это исходный код первого MVP, а не опубликованный Telegram-бот. Браузерный режим можно запустить сразу. Для настоящего Telegram нужны ваш бот, его токен и HTTPS-адрес. Токен не отправляйте в чат и не добавляйте в Git. Проверки на физическом iPhone и в вашем Telegram требуют ручного выполнения.

## Monochrome Alpine · запуск на Windows

Интерфейс переработан в чёрно-белую систему: компактная SVG-заставка, новые главная/катание/аналитика/история/профиль, белые основные действия, читаемые значения и отдельная загрузка карты. Реальные GPS-расчёты, SQLite и серверная проверка initData сохранены.

**Текущий сценарий — существующий Tailscale Funnel на Windows, без покупки сервера или домена.** Главная инструкция: **[START_WINDOWS_RU.md](docs/START_WINDOWS_RU.md)**. Для обновления из ZIP сохраните .env и data, выполните 01_INSTALL.bat, затем 04_TELEGRAM.bat. Git не требуется.

04_TELEGRAM.bat запускает **Mini App Only**: production HTTP, SQLite и проверка подписи работают, polling выключен и Telegram API не вызывается. Кнопка Mini App настраивается в BotFather. 08_FULL_BOT.bat явно включает полноценного бота при разрешённом прямом/proxy-доступе к API. Существующий Funnel проверяется и переиспользуется, но не создаётся автоматически.

Установщик теперь загружается без dotenv/node_modules, избегает ненужного npm ci и пересобирает dist при изменении исходников. Build ID виден в интерфейсе и /api/status. .env и данные не заменяются. Скриншоты и результаты: [PREMIUM_UI_REVIEW.md](docs/PREMIUM_UI_REVIEW.md).

Предыдущие файлы постоянного deployment сохранены для совместимости; они не обязательны для текущего Windows/Funnel-сценария. Сетевые исправления 87bd5ae не откатывались.

## Что реализовано

- Бот grammY: `/start`, `/help`, `/stats`, кнопка Mini App и меню бота.
- Проверка Telegram `initData` на сервере: HMAC-SHA256, постоянное по времени сравнение, срок 1 час, защита от повторяющихся полей. `initDataUnsafe` не используется.
- React-приложение: главная со статистикой сезона, запись, карта Leaflet, история/статистика с фильтрами, детализация маршрута/спусков, редактирование профиля.
- GPS: browser `watchPosition` или явный выбор Telegram LocationManager с опросом раз в 5 секунд, пауза, продолжение, локальный черновик и отправка на сервер после завершения.
- SQLite: пользователи, профили, сессии, GPS-точки, спуски. Все API-запросы ограничены владельцем. Повторная отправка одной сессии с тем же UUID не создаёт дубликат.
- GPX до 5 МБ / 40 000 точек: проверка XML, запрет DTD/ENTITY, ограничение вложенности, проверка координат и времён. Импортированные записи входят в личную статистику.
- Три синтетических демо-трека. Хранятся с `source=demo`, показываются отдельно и исключены из главной и `/stats`.
- Карта с началом/концом маршрута, цветом скорости, выбором отдельного определённого спуска. Район определяется положением трека, курорт вводится пользователем. Данных о трассах и подъёмниках приложение не выдумывает.

Социальные функции пока не реализованы. Точные координаты доступны только самому райдеру. Это не навигационное или аварийно-спасательное средство.

## Технологии и структура

Node.js **24 LTS** (встроенный `node:sqlite`), TypeScript, Express 5, grammY, React 19, Vite, Tailwind 4, Leaflet/OpenStreetMap, Zod, fast-xml-parser. SQLite выбран без внешнего сервера и сборки нативного драйвера на Windows. Некоторые версии Node могут выводить предупреждение об экспериментальном SQLite API.

```text
frontend/src/       экраны, Telegram API, карта, GPS и локальный черновик
backend/src/        Express API, авторизация, бот, SQLite и GPX
shared/track.ts    общий воспроизводимый алгоритм трека
shared/demo.ts     явно синтетические учебные маршруты
tests/             расчёты, безопасность, API, бот; browser/ — Playwright
fixtures/          примеры GPX для ручной проверки
docs/              ограничения, тестирование, развитие
```

Одна база SQLite, один Node-сервер. В production сервер отдаёт и API, и собранный frontend. В разработке Vite перенаправляет `/api` на backend. Docker и внешняя база не нужны.

## Установка на Windows для разработчика

Для запуска двойным щелчком без Git используйте [START_WINDOWS_RU.md](docs/START_WINDOWS_RU.md). Команды ниже — альтернативный сценарий разработки.

1. Установите Git и **Node.js 24 LTS** с официального nodejs.org. Откройте PowerShell заново.
2. Клонируйте репозиторий и перейдите в него:

```powershell
git clone https://github.com/F1askO1/test.git
cd test
node --version
npm ci
Copy-Item .env.example .env
npm run dev
```

`npm ci` использует lockfile. Для уже подготовленной облачной среды используйте существующий checkout; создавать worktree не нужно.

Frontend: `http://localhost:5173`. API: `http://127.0.0.1:3001/api/health`. Эти адреса предназначены только для локальной разработки. В `.env` первоначально `DEV_AUTH=true`, `BOT_TOKEN` и `APP_URL` пустые. Это один локальный тестовый пользователь, а не подмена Telegram-авторизации в production.

Если удобнее, запустите в двух терминалах:

```powershell
npm run dev:backend
# Во втором терминале:
npm run dev:frontend
```

Не публикуйте dev-сервер или API с `DEV_AUTH=true` в интернет. Все посетители получат один тестовый аккаунт. Для проверки Telegram используйте сборку и настоящий токен, как описано ниже.

## Бот через @BotFather

1. В Telegram откройте проверенного `@BotFather`.
2. Отправьте `/newbot`, задайте имя и уникальный username, оканчивающийся на `bot`.
3. Скопируйте выданный токен **только в локальный `.env`**:

```dotenv
BOT_TOKEN=ваш_токен_из_BotFather
APP_URL=https://ваш-публичный-адрес
DEV_AUTH=false
NODE_ENV=production
```

Это пример структуры, не настоящий секрет. При утечке немедленно перевыпустите токен в BotFather.

При старте backend зарегистрирует `/start`, `/help`, `/stats` и кнопку меню через `setChatMenuButton`. Кнопка «Открыть приложение» в `/start` использует `web_app` InlineKeyboardButton. Тестируйте в **личном чате с ботом**. На один токен запускайте только один polling-процесс. Если у бота раньше был webhook, удалите его штатными средствами Bot API перед polling; приложение не сбрасывает webhook автоматически.

Можно также настроить Main Mini App через `/mybots` → ваш бот → Bot Settings → Configure Mini App (названия пунктов могут меняться). Для ручной настройки меню используйте `/setmenubutton` и тот же HTTPS URL. `/setdomain` относится к другим механизмам авторизации и не заменяет проверку initData.

## Временный HTTPS для разработки (не production)

Для постоянной работы следуйте DEPLOYMENT_RU.md. Следующий пример оставлен только для временной проверки. Нужен публичный HTTPS-адрес, который ведёт на локальный **production-сервер** с frontend и API. Например, установите официальный `cloudflared` (отдельная утилита, в проект не входит), затем:

```powershell
npm run build
# В отдельном терминале:
cloudflared tunnel --url http://127.0.0.1:3001
```

Скопируйте полученный адрес `https://….trycloudflare.com` в `APP_URL`. Укажите `BOT_TOKEN`, `DEV_AUTH=false`, `NODE_ENV=production` в `.env`, затем:

```powershell
npm start
```

В личном чате с ботом отправьте `/start`, нажмите «Открыть приложение». Снаружи Telegram страница откроется, но API корректно откажет без initData. Перезагрузка страницы не создаёт Telegram-авторизацию: открывайте через бота.

Quick Tunnel временный, без гарантии доступности; адрес обычно меняется после перезапуска. При смене обновите `APP_URL`, перезапустите сервер и заново отправьте `/start`. Туннель не был запущен агентом и требует вашей установки/проверки. Альтернатива — ваш HTTPS reverse proxy или ngrok. Не используйте HTTP для публичного Mini App и не отключайте проверку TLS.

Для постоянного сервера настройте HTTPS reverse proxy, переменные окружения, перезапуск Node-процесса и резервное копирование SQLite. `HOST=127.0.0.1` оставляйте для туннеля на той же машине. `TRUST_PROXY=1` задавайте только если запросы действительно проходят через один доверенный proxy; это влияет на определение IP и rate limits.

## GPS, импорт и демо на телефоне

1. В Telegram откройте Mini App из бота. Разрешите геолокацию Telegram и доступ к ней в приложении. На iPhone включите «Точная геопозиция».
2. Откройте «Катание», укажите курорт и название поездки по желанию, нажмите «Начать GPS-запись». Сохраняйте Mini App открытым и телефон разблокированным.
3. Пройдите пешком несколько десятков метров на улице; проверьте рост числа точек и линию. На месте GPS может дрейфовать, особенно в помещении.
4. При отказе browser GPS попробуйте явно переключить источник на Telegram LocationManager (если доступен в установленной версии Telegram). Это опрос, а не фоновая подписка. Вручную подтвердите необходимые запросы Telegram.
5. «Приостановить» прекращает получение координат. После «Возобновить» промежуток не соединяется линией. «Завершить и сохранить» отправляет данные; при ошибке черновик остаётся, можно повторить.
6. Закройте и повторно откройте Mini App: сохранённый локально незавершённый трек можно продолжить или отправить. Локальное хранилище зависит от WebView: Telegram/ОС могут его очистить.
7. Для теста дома нажмите один из трёх демо-маршрутов. В деталях и истории будет метка ДЕМО. На главной реальные показатели не изменятся. В статистике выберите «Демонстрация» и «Всё время».
8. Сохраните `fixtures/sample.gpx` на телефон (iCloud Drive / Files), включите «Учебный GPX» и выберите «Импортировать GPX». Этот пример синтетический и должен оставаться демо. Для своего настоящего трека оставьте флажок выключенным. Откроется карта и расчёты. Высоты GPX без вертикальной точности **не порождают достоверный перепад или спуски**: статус останется «Не определено».
9. Откройте историю после перезапуска — данные должны остаться. Удалите ошибочный трек через детали и подтвердите действие.

## Как считаются показатели

Подробности в [docs/algorithms.md](docs/algorithms.md). Общее расстояние — движение по пригодным GPS-точкам, включая подъёмы. Отдельно считается дистанция уверенно определённых спусков. Остановки исключаются из движения, разрывы не соединяются. Скорость вычисляется из расстояния и времени; поле скорости от устройства не считается доказательством рекорда. Максимальная скорость — максимум между соседними пригодными точками, это любительская оценка, не сертифицированный замер.

Дни/фильтры и график используют часовой пояс устройства и дату начала сессии. Сезон — с 1 июля по 30 июня. Поездка — общее введённое название у нескольких сессий. Переход через полночь пока не разбивает одну сессию по дням. Число дней не является числом запусков. График показывает последние 14 дней **с записями** в выбранном периоде. Рекорды в статистике относятся к выбранному фильтру.

Первые координаты определяют район на карте; обратного геокодинга нет. Название курорта пользователь вводит вручную, приложение не выдаёт его за проверенное.

## Ограничения веб-трекинга

- Telegram Mini Apps и браузерная геолокация не гарантируют работу при блокировке телефона, закрытии или сворачивании Telegram. Приложение сообщает об отсутствии свежих координат; вымышленных точек нет.
- `watchPosition` требует разрешения и безопасного контекста (HTTPS; localhost разрешён для разработки). Telegram LocationManager доступен не во всех клиентах и выдаёт отдельные местоположения.
- При скрытии окна, паузе, плохой точности, отбрасывании выброса или интервале более 35 секунд трек разделяется. Это намеренная потеря части дистанции ради честности данных.
- Высота и вертикальная точность часто отсутствуют на iPhone. Тогда дистанция и скорость доступны, спуски/подъёмы/перепад могут остаться неопределёнными.
- Локальная запись — best effort, не гарантированная защита от очистки хранилища. Пока GPS активен, черновик сохраняется после каждого обновления. Законченные треки живут в SQLite на сервере; базу нужно сохранять на постоянном диске.
- Страница и карта не обещают офлайн-запуск. Если уже открытое приложение потеряло интернет, GPS-черновик сохраняется, но картографические тайлы/синхронизация могут не работать.
- OSM стандартные тайлы требуют интернет, атрибуцию и соблюдение [tile usage policy](https://operations.osmfoundation.org/policies/tiles/). Нет массовой загрузки/предзагрузки тайлов. Для массовой аудитории потребуется подходящий поставщик тайлов; бесплатный публичный сервер не имеет SLA.
- Продолжительность записи ограничена 40 000 точками. Автоматической синхронизации активного трека в фоне нет. Сообщение «нет свежих точек» появляется через 25 секунд, когда JS продолжает выполняться.
- Долгое открытие Mini App может привести к истечению initData через час. Если API просит повторную авторизацию, приостановите запись, переоткройте через бота и сохраните восстановленный черновик.

## Сборка и автоматические тесты

Запускайте команды из корня репозитория:

```powershell
npm run check
npm test
npm run build
# Для браузерных тестов (сначала build):
npx playwright install chromium
npm run test:e2e
```

`npm test` проверяет расстояния, скорость, точность, выбросы, разрывы, остановки, разделение спусков/подъёмов, отсутствие достоверных высот, безопасный GPX, Telegram-подписи и срок, приватность API, повторную отправку, профиль, каскадное удаление и сохранность SQLite. Тест бота использует настоящие обработчики grammY, но **имитирует Telegram API** и не доказывает доступность настоящего бота.

Playwright проверяет мобильный viewport в Chromium: демо, реальный импорт, сохранение профиля, перезагрузку истории, удаление, GPS с синтетической геолокацией, восстановление черновика и отказ в разрешении. Это не физический iPhone. В Linux можно указать системный браузер через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; в Windows обычно не нужно. Дополнительные ручные проверки: [docs/testing.md](docs/testing.md).

Для обычного запуска production сначала задайте безопасные `.env`, затем `npm run build` и `npm start`. Собранные файлы находятся в `dist/`, база — в `data/`. Не удаляйте `data/` при обновлении. Для резервного копирования остановите приложение и сохраните каталог `data` целиком вместе с SQLite WAL/SHM, если они есть.

## Источники и статус проверки

Референсы продукта: [Skill](https://skill.ski/winter/ru), [FAQ](https://skill.ski/ru/faq.html), [App Store](https://apps.apple.com/ru/app/id1329688004). Реализация SlopeMate самостоятельная: свой интерфейс и SVG-иллюстрация, чужие изображения/логотипы/код не использованы.

Официальные технические источники для проверки: [Telegram Mini Apps / LocationManager](https://core.telegram.org/bots/webapps#locationmanager), [проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [Bot API](https://core.telegram.org/bots/api), [MDN Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition).

В текущей облачной среде попытка прочитать эти страницы была заблокирована сетевой политикой (HTTP 403 от proxy); содержимое источников не подтверждено чтением. Домены добавлены в черновик настроек, но это не применяет политику автоматически. Перед публикацией проверьте актуальную документацию и выполните ручные Telegram/iOS проверки. Проверки подписи и поведения API выполнены локальными тестами, а не реальными данными Telegram.

Дальнейшее развитие: [docs/roadmap.md](docs/roadmap.md).

Результаты текущего запуска и непроверенные пункты: [docs/validation.md](docs/validation.md).

## Читаемая карта Домбая

Карта занимает основной экран; поиск, слои и информация о курорте открываются отдельно. Тонкие линии зависят от масштаба. Проверка на присланных реальных 136 участках и 13 подъёмниках, скриншоты и ограничения подложки: [MAP_READABILITY_RU.md](docs/MAP_READABILITY_RU.md).
