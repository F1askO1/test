# Результаты проверки 5 ноября 2026

Выполнено в текущей Linux cloud-среде, Node.js 24.22.1:

- `npm ci --no-audit --no-fund`: воспроизводимая установка по lockfile прошла.
- `npm run build`: TypeScript, Vite и backend compilation прошли.
- `npm test`: **17 passed**, 0 failed, 0 skipped. Расчёты, GPX, авторизация, API, сохранение SQLite после переоткрытия, бот с mock Telegram API.
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`: **3 passed**, 0 failed. Мобильный viewport iPhone 13 в Chromium: навигация, исключение демо с главной, GPX, профиль, повторное открытие, удаление; GPS с искусственными координатами, пауза, восстановление черновика, имитация сетевого сбоя и повторная отправка; отказ в разрешении GPS. Сборка соответствует проверенной версии интерфейса.
- `npm run dev`: frontend и backend стартовали. Реальные HTTP-запросы к `/api/health`, `/api/me` через Vite proxy и frontend HTML вернули 200 и ожидаемые данные.
- `git diff --check`: прошёл. `.env`, SQLite, node_modules, сборка и результаты браузерных тестов исключены из Git. Пользовательский `eror.md` сохранён.

Что пока **не проверено**:

- Реальная регистрация и ответы бота Telegram, кнопка/меню, настоящая initData: BOT_TOKEN и HTTPS APP_URL не предоставлены.
- Физический iPhone/Android, их GPS, фоновые ограничения, разрешения и Telegram LocationManager: требуется ручной сценарий из testing.md. Chromium-эмуляция не заменяет iOS WebView.
- Доступность стандартных OSM-тайлов в условиях реальной мобильной сети. Рендер маршрутов и управление картой проверены, но браузерный тест не подтверждает успешную загрузку всех внешних тайлов. В UI есть сообщение об ошибке подложки.
- Содержимое официальных страниц Skill, Telegram, MDN: чтение заблокировал proxy с 403. Не заявляется, что источники изучены. Черновик разрешённых доменов сохранён, но runtime-политика не была обновлена/проверена после публикации.
- Установка и запуск на физической Windows-машине. Команды и зависимости подобраны под Windows и Node 24; реальный запуск выполнен на Linux.
- Публикация облачной среды, развёртывание постоянного HTTPS-сервера и восстановление в новой задаче.

Конфигурационный черновик сохранён: install_script, start_skill, домены внешних источников/Telegram/OSM. Это не публикация и не развёртывание Telegram-бота. Пользователь должен просмотреть и сохранить изменения в настройках среды и опубликовать среду, если хочет использовать эту конфигурацию в новых задачах.
