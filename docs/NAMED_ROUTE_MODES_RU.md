# Домбай: логические маршруты и два режима карты

Проверка 7 ноября 2026 года использует неизменный настоящий пакет `map-sources/prepared/dombay-2026-11-06.slopemap` и `tests/fixtures/dombay/resort.osm`. Пакет импортирован только в `artifacts/named-routes/map-data`. SQLite, `.env`, исходные GPS-точки, авторизация, Tailscale и загрузчики не менялись.

## Что подтверждено источниками

[Таблица соответствия с OSM-ссылками](DOMBAY_NAMED_ROUTES.md) и [машиночитаемый аудит](DOMBAY_NAMED_ROUTES.json) содержат имена, сложности, геометрические компоненты, членство в relations и общие исходные node ID. Восстановление отчёта: `node --import tsx scripts/audit-named-routes.ts`.

Список десяти имён получен из задания пользователя. Каталог https://dombai-kd.ru/karta-trass/ независимо прочитать не удалось: HTTPS CONNECT отклонён прокси среды с HTTP 403. Поэтому совпадение имени OSM не объявляется подтверждением полной официальной геометрии или официальной сложности.

«Поляна Лии» не привязана к геометрии. «Выезд на лесную» не переименован в «Лесную». У «Лесной» линейный объект имеет сложность `easy`, площадной — `intermediate`; конфликт сохранён. Номера `piste:ref` в линейных объектах набора отсутствуют. Общие node ID подтверждают соединения частей «Домбайской поляны», «Сулахата», «Старого Домбая» и «Домбай 2». Все девять групп имеют один связный линейный компонент, но это не доказательство полноты официального маршрута.

## Как работает представление

В панели **Слои → Режим карты** доступны:

- **Основные трассы**, по умолчанию: связанные части с достоверным совпадением имени образуют логическую группу. Поиск и выбор открывают карточку группы со всеми исходными OSM ID, сложностями, площадями и оговоркой о подтверждённости. Остальные реальные линии остаются тонким серым контекстом и доступны для выбора. Три именованные площади выделены цветной полупрозрачной заливкой, остальные пять — спокойной нейтральной.
- **Подробная карта OSM**: все исходные достоверные элементы с собственной классификацией и индивидуальным выбором.

Объединяются только цепочки с общей принадлежностью, совместимой сложностью и настоящими общими вершинами. Развилки сохраняются. Несвязанные фрагменты не соединяются прямой линией, близость не считается доказательством общего маршрута. Геометрическая генерализация применяется к отдельному представлению, сохраняя узлы соединений и ссылки на исходные объекты. GPS map matching и аналитика фрирайда используют полную исходную геометрию независимо от режима.

На одинаковой камере теста число цветных цепочек трасс сократилось с 29 до 15. Это **не** число официальных маршрутов: именованные группы могут разветвляться. Общее число отрисованных путей — 43 в основном и 42 в подробном режиме, поскольку составление топологического графа меняет разбиение цепочек; исходных объектов по-прежнему 149. Польза основного режима — визуальная иерархия и совместный выбор, а не удаление геоданных. На снимках общий географический рисунок остаётся похожим: отдельные реальные линии намеренно сохранены.

В информации о курорте теперь раздельно показаны совпавшие имена, линейные части, площадные зоны и подъёмники. Счётчики 136 и 131 из исходного импорта не выдаются за количество официальных маршрутов.

## Что уже нарисовано на OpenTopoMap

Проверен публичный исходный стиль OpenTopoMap, снимок `60c50cb8329d67c8556cd9f25b4a8e50bfc19c91`:

- [aerialways.xml](https://github.com/der-stefan/OpenTopoMap/blob/60c50cb8329d67c8556cd9f25b4a8e50bfc19c91/mapnik/styles-otm/aerialways.xml): канатные дороги и гондолы с z12, остальные подъёмники с z13, тонкие чёрные линии с условными знаками;
- [opentopomap.xml](https://github.com/der-stefan/OpenTopoMap/blob/60c50cb8329d67c8556cd9f25b4a8e50bfc19c91/mapnik/opentopomap.xml): подключение этого слоя;
- в проверенных XML-стилях и таблице импорта не найдено правил `piste`, `skiing`, `ski_route`. Это **не доказывает**, что текущая серверная версия растра не содержит трасс.

Поэтому наши трассы автоматически не скрываются. Защита от двойного изображения подъёмников действует на документированных масштабах OpenTopoMap. Для реального сравнения есть переключатель **Наш слой подъёмников поверх подложки (сравнение)**. Если на фактически загруженном растре подтверждены также лыжные трассы, можно явно включить **Трассы уже нарисованы в подложке (после проверки)**. Этот параметр выключен по умолчанию. Выбранный объект может подсвечиваться поверх растра намеренно. При fallback на OSM наши векторные слои восстанавливаются. Отсутствие любых дублей на текущих внешних тайлах в облаке не подтверждено.

Растровый слой нельзя честно очистить от отдельных линий средствами Leaflet. CSS-маски стирали бы также рельеф. Законный вариант чистой топографии — свой XYZ-рендер из OSM и DEM с подходящими лицензиями либо провайдер, прямо разрешающий использование и не включающий собственные лыжные слои. [README OpenTopoMap](https://github.com/der-stefan/OpenTopoMap/blob/60c50cb8329d67c8556cd9f25b4a8e50bfc19c91/README.md) описывает самостоятельный сервер и CC-BY-SA для онлайн-карт, а также прекращение развития старого растра в пользу векторов. У Garmin-карт другая лицензия; они здесь не используются. Гарантия доступности публичных тайлов отсутствует.

Подготовлено необязательное подключение такой чистой топографии через `map-sources/basemaps.json`. По умолчанию `cleanTopography: null`, новый сервис не подключён. Формат объекта:

```json
{
  "cleanTopography": {
    "url": "https://YOUR-TILE-HOST.example/{z}/{x}/{y}.png",
    "name": "Своя топография",
    "attribution": "© OpenStreetMap contributors; DEM: УКАЖИТЕ ИСТОЧНИК",
    "licenseUrl": "https://YOUR-TILE-HOST.example/license",
    "termsUrl": "https://YOUR-TILE-HOST.example/terms",
    "maxNativeZoom": 17,
    "skiLines": "absent"
  }
}
```

Это пример формы, не работающий endpoint. Владелец должен подтвердить права, лимиты, атрибуцию, реальный native zoom и отсутствие как трасс, так и подъёмников в растре. Проверка конфигурации проверяет формат, не юридические права: HTTPS, XYZ, отсутствие credentials/query в URL тайлов и корректный диапазон native zoom. Секреты/API-ключи во frontend не добавляются. После изменения нужна сборка; валидный источник появляется в слоях, использует существующий монитор покрытия и fallback. Настоящий чистый рельеф этим коммитом не развёрнут и не проверен.

Внешние тайлы в облачной среде запрещены, поэтому браузерный прогон явно использовал offline-режим. Во всех кадрах 24 видимых тайла, 0 загруженных, 24 ошибки, покрытие 0%. В среде с разрешёнными тайлами повторите строгий прогон в PowerShell, импортируя пакет в отдельный каталог:

```powershell
$env:SLOPEMATE_TEST_MAPS="$PWD\artifacts\named-route-check\map-data"
npm run maps:package -- import map-sources/prepared/dombay-2026-11-06.slopemap $env:SLOPEMATE_TEST_MAPS
Remove-Item Env:SLOPEMATE_MAP_OFFLINE -ErrorAction SilentlyContinue
npm run build
npm run test:e2e -- named-routes.spec.ts -g "REAL Dombay"
```

Без offline-флага тест требует полного покрытия viewport, а не одного тайла. Он делает пять кадров с одинаковой камерой и дополнительные кадры сравнения растра с нашим слоем подъёмников при OpenTopoMap. При настроенной чистой топографии используется она. Проверить нужно также реальный iPhone/Telegram WebView: касание тонких линий, переключение режимов и качество подложки. Автоматический Chromium — не физический iPhone.

## Выполненные проверки

`npm run check`, `npm run build`, `npm test`: 110 модульных тестов прошли. Полный браузерный прогон с реальным тестовым пакетом и явным offline-флагом: 23 прошли, 1 строгий тест настоящей топографии пропущен. Отдельный тест политики растрового слоя использует mock SVG-тайлы и не доказывает наличие настоящего рельефа.

Тесты охватывают совпадение имён, неоднозначные теги, несколько relations одного way, несвязанные части, совместимые цепочки и развилки, конфликт сложности, неизменность исходных объектов/GPS-анализа, безопасность конфигурации подложки, совместный выбор, отдельные площади и переключение режимов. Для окончательной приёмки картографии остаётся реальное сравнение растровых и векторных линий с полностью загруженной топографией в разрешённой сети.
