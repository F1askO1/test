# GPS Engine 2.0

Новый анализ получает единый Point: lat/lon, timestamp UTC milliseconds, необязательные alt/accuracy/altAccuracy/speed, breakBefore. Источники browser, Telegram, GPX и native используют одну серверную обработку. BOT_TOKEN/источник записи не делает GPS автоматически точным.

## Версии и совместимость

Сохранён track-v1.ts с прежним поведением по умолчанию. Старые записи без engineVersion открываются v1; сохранённый summary не заменяется. Новые получают engineVersion=2, altitudeQuality и отдельные liftDistance/liftSeconds/pisteMatches. Edges новых сессий сохраняются вместе с версионным анализом: обновление геоданных не меняет историю молча. В списке истории edges не отправляются. SQLite не удаляется; новые таблицы привязки добавляются через CREATE IF NOT EXISTS. Схема помечается user_version=2 без пересоздания таблиц пользователей/сессий.

## Метод

1. Проверка координат/времени, повторов, точности до 65 м и неправдоподобных скоростей прежнего фильтра. Явный разрыв допускает новое место, но соединяющее расстояние равно нулю.
2. Временное окно 45 секунд при известной вертикальной точности, до 90 секунд при неизвестной. Медианы начала/конца окна и порог, зависящий от точности, определяют устойчивую тенденцию. Окно не пересекает gap. Краткий начальный unknown-фрагмент может быть классифицирован по последующему подтверждению.
3. Неизвестная точность высоты GPX допускает preliminary direction при устойчивой тенденции, но **не достоверный вертикальный рекорд**. Отсутствующая/шумная высота остаётся unknown. Нет привязки высоты к DEM и нет обещания достоверности GPX-altitude.
4. Короткие stop/unknown до 25 секунд могут соединить фрагменты спуска. Поездка вверх, длинный отдых и gap всегда разрывают серию. Минимум 50 м/15 с на спуск. Прогнозируемый тип и фактически измеренный перепад — разные вещи.
5. Скорость для отображения/максимума — медиана локальных координатных скоростей, без доверия одиночному speed=999 от датчика. Дистанция остаётся геодезической по принятым точкам с deadband. Это не гарантирует от всех плавных GPS-дрейфов; абсолютное ограничение прежнего фильтра 45 м/с (162 км/ч) сохранено.
6. При наличии геометрии пространственная сетка выбирает близкие линии. Подтверждённый lift исключается из спусков; метрики подъёмников отдельны. Вероятная привязка к трассе требует истории, приемлемой точности, продвижения вдоль линии и отрыва от альтернатив. Полное прохождение трассы не объявляется.

Доверенный перепад накапливается только из измерений с известной вертикальной точностью, с deadband; систематическая ошибка прибора всё ещё возможна. Показатель общего расстояния по-прежнему включает все виды движения. descentDistance и liftDistance разделяют распознанные типы; unknown не выдаётся за спуск. Нулевое liftDistance в UI называется «Не определены», а не доказанным отсутствием подъёмников.

## Производительность и хранение

Активный анализ вынесен в Web Worker: один выполняемый и один последний ожидающий job. Нет полного анализа многотысячного трека на главном потоке после каждой точки. Пока worker работает, UI показывает последний завершённый результат. Анализ в worker пока полный, **не заявлен математически инкрементальным**. В тесте 12 000 синтетических точек без геометрии укладываются в 5 с; это не iPhone benchmark. Map matching ограничен последними 40 точками и пространственным индексом. Анализ больших импортов на сервере синхронный; при дальнейшем росте нагрузки потребуется серверный worker.

IndexedDB записывает новую точку по ключу [userKey,timestamp] транзакционно вместе с metadata. Legacy localStorage сначала переносится полностью; только после подтверждённого commit резервная копия сокращается до первых 128 точек. При неуспешной миграции прежняя полная копия не удаляется. Очередь сохраняет порядок; timestamp устраняет дубли. Новый старт ждёт восстановления. Ошибка/квота отображается, нельзя считать запись гарантированно сохранённой при отказе хранилища. Точки без сигнала не создаются. Возвращение/пауза/устаревшие координаты дают breakBefore. Серверный UUID обеспечивает идемпотентную повторную синхронизацию.

Нет сетевого фонового sync web-черновика без действительной Telegram initData: завершение/повтор выполняются пользователем в открытом Mini App. После изменения HTTPS origin IndexedDB/localStorage недоступны другому origin. Не меняйте Funnel URL посреди записи.

## Точность

Unit/integration tests используют явно синтетические траектории. Они проверяют одиночный длинный спуск, постепенный уклон, две серии/подъём, короткий/длинный stop, высоту GPX, отсутствие высоты, дрейф, скачок, gaps, неоднозначность трасс, lift и остановку, длинный массив, сохранённую v1 историю. Полевой precision/recall/F1 и ошибка ETA **не измерены**. Отчёт синтетической оценки создаёт `npm run gps:evaluate`; его показатели нельзя переносить на реальные курорты. Нужны реальные лицензированные треки с ручной разметкой и реальная модель GPS iPhone.
