# Архитектура web + native GPS

## Web

useRecorder → последовательная очередь IndexedDB (metadata + точки по timestamp) → Web Worker GPS Engine 2.0 → явное завершение /api/sessions с UUID → SQLite. При ошибке сети черновик остаётся. Старая localStorage-копия мигрируется после успешного чтения; не удаляется до durable commit. Скрытие, пауза, отсутствие свежей точки отмечают gap. Возвращение продолжает активный watch при поддержке WebView; полный restart восстанавливает черновик с явным продолжением. Потерянные координаты не интерполируются.

## Нативный компонент

`ios/SlopeMateRecorder` — SwiftUI + CLLocationManager, iOS 17+. XcodeGen project.yml создаёт настоящий Xcode project на Mac. Никакого BOT_TOKEN в нём нет. После явного согласия запись начинается в нативном foreground; Background Mode разрешает поддерживаемые системой location updates. Точки добавляются в NDJSON и синхронизируются на диск, metadata атомарна. Файлы защищены until first authentication, чтобы запись после первого unlock могла продолжаться при блокировке. При ошибке диска запись останавливается с сообщением. Нет бесконечного невидимого JS.

Незавершённая запись обнаруживается при следующем запуске, продолжение — кнопкой с разрывом. Завершённые треки загружаются после завершения, при foreground и восстановлении пути NWPathMonitor, если iOS исполняет приложение. Во время отсутствия интернета остаются на устройстве. Автоматический запуск сетевого кода у полностью приостановленного процесса не обещается. Есть ручной повтор синхронизации. Неполная последняя NDJSON-строка после аварии не мешает восстановить остальные полные строки.

## Привязка и границы доступа

1. В Telegram с валидным initData POST /api/recorder/pair создаёт криптографически случайный одноразовый код (5 минут).
2. Ссылка slopemate-recorder://pair содержит код и HTTPS origin. Нативный экран показывает домен и просит подтверждение; не отправляйте эту ссылку другим людям. Это секрет на время привязки.
3. POST /api/device/redeem атомарно потребляет хеш кода и выдаёт 256-битный device key. Сервер хранит только SHA-256; iPhone — Keychain ThisDeviceOnly. HTTPS-сертификаты проверяются, redirect при передаче ключа запрещён.
4. POST /api/device/sessions принимает **только сессии владельца ключа**; клиент не задаёт user ID. UUID повторной загрузки возвращает прежнюю сессию; запись транзакционна. Оборванный HTTP body не создаёт половину сессии. Обычные /api/me/трек/profile не открываются device key.
5. Ключ можно отозвать из Telegram-профиля. Код просрочен/повторно использован — 401. Новый пользователь не может присвоить чужой UUID. Привязка к другому аккаунту запрещена до завершения/синхронизации старых треков.
6. Локальные треки не удаляются автоматически даже после подтверждения сервера. Устройство помечает synced только после ответа с тем же UUID.

В SQLite добавляются recorder_pairs и recorder_devices без удаления существующих данных. Серверный BOT_ENABLED=false, Telegram initData HMAC, приватные GPS, Mini App Only, Tailscale и Full Bot сохраняются. Proxy Telegram не используется для нативного клиента; он обращается к уже существующему HTTPS endpoint.

## Сценарий пользователя

Установить companion через Mac/Xcode/signing → открыть профиль SlopeMate в Telegram → привязать → подтвердить свой HTTPS-домен в companion → начать запись в companion → убрать телефон в карман → завершить → дождаться sync → переоткрыть историю Telegram. Нет ручного экспорта GPX. Нативная запись пока не объединяется в реальном времени с web-черновиком; не запускайте оба рекордера одновременно для одного катания.

Windows не собирает iOS приложение. Бесплатный Apple signing имеет ограничения; для TestFlight/App Store обычно нужна платная Apple Developer Program. Нет необходимости менять backend или покупать VPS/домен. Критические ограничения и реальные испытания: BACKGROUND_GPS_TEST_REPORT_RU.md.
