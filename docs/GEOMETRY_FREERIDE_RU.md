Это диагностические кандидаты, **не автоматическое основание для объединения** соседних трасс.

Принадлежность старых ways к нескольким `route=piste` relations восстановить из пакета нельзя. Новый нормализатор сохраняет теги и все родительские relation ID/имя/сложность; несовпадающая сложность не выбирается произвольно. Загрузчики, Overpass/Geofabrik-скрипты не менялись. Региональный PBF из прошлого сообщения превышает лимит передачи этой среды 32 MiB. Для окончательного разбора площадей/relations нужен небольшой исходный `resort.osm` с тегами, который уже умеет готовить `npm run maps:extract -- <regional.osm.pbf> dombay`. Рабочий набор для этого менять не требуется.

Альтернативный `normalizeOpenSkiData` проверен отдельно: он принимает только LineString/MultiLineString, разрезает MultiLineString на части и устраняет повторения по производному feature ID/номеру части, но не по OSM-геометрии. Поэтому разные source features там тоже могут геометрически перекрываться; слой представления обрабатывает точные совпадения независимо от импортера. Этот путь не использовался для присланного регионального пакета; приписывать ему происхождение линий Домбая оснований нет.

## Как работает представление

`shared/ski-display.ts` строит отдельный граф точных рёбер. Пространственный индекс ограничивает поиск вершин; точно коллинеарные частичные наложения разрезаются по существующим координатам. Один общий участок рисуется один раз и хранит ссылки на все source features. При конфликте сложности он нейтральный серый точечный, карточка перечисляет исходные ID и сложности. Близкие линии не объединяются автоматически.

Рёбра с одинаковыми источниками/стилем соединяются только через вершины степени два. Это устраняет круглые точки стыков и сброс фазы пунктира на каждой вершине. Никакие координаты не перемещаются; нет выпрямления поворотов и синтетических осевых линий. Масштабные веса и область выбора Canvas 7 CSS px сохранены. Дополнительно единый географический picker карты выбирает ближайший объект в пределах 9 CSS px независимо от перекрывающих Canvas-панелей.

Три неоднозначных замкнутых контура показаны отдельно: слабая заливка, нейтральная тонкая граница только с z16; они доступны через поиск и карточки с предупреждением. Для явного `area=no` настоящий замкнутый лыжный маршрут остаётся линией. В «Слои» есть диагностический переключатель **«Исходные линии OSM (диагностика)»**. Он позволяет сравнить исходные штрихи с представлением без изменения центра и масштаба.

1273 рёбра не означают 1273 трассы: это 146 незамкнутых исходных объектов, топологически разбитых на рёбра. 149 цепочек рендера также не являются числом официальных маршрутов. Все 149 исходных объектов и 1787 исходных координат сохранены.

Подтверждён дефект касаний: Canvas личного трека создавался и при пустом треке и перекрывал нижние Canvas-панели, так что события не доходили до линий. Пустой Canvas больше не создаётся; единый picker выбирает OSM/GPS по расстоянию, а не порядку DOM-панелей. Тест реального касания воспроизвёл дефект до исправления и проходит после него.

Дополнительно повторный прогон выявил гонку удаления Canvas на zoom: отложенный redraw мог вызвать `clearRect` после уничтожения контекста. Исправление: постоянные рендереры на срок жизни карты, замена только путей.

Проверка React/Leaflet не выявила накопления предыдущих слоёв: пути очищаются, Canvas переиспользуются и удаляются вместе с картой; повторные изменения масштаба не увеличивают их число. Выделение находится в отдельном слое и очищается. Подъёмники имеют отдельный тип, pane и стиль; их геометрия не смешивается с трассами. Дубли станций по одной координате не рисуются повторно. Направление без подтверждения не придумывается.

## Подложка: исправленный fallback и остающийся сетевой блок

Основной слой — существующий OpenTopoMap (рельеф/подписи, CC-BY-SA), резерв — OpenStreetMap Standard (обычная карта, **не топографическая замена**). У каждого viewport считаются успешные/ошибочные тайлы. Различаются loading, ready, partial, unavailable. Одна ошибка не объявляет работающий слой недоступным. При трёх ошибках без успеха, завершении загрузки без успеха либо тайм-ауте 12 секунд включается резерв. На повторных перемещениях таймер обновляется. Бесконечного перебора провайдеров нет; обратный переход к рельефу — явным действием в панели слоёв. Диагностика провайдера и счётчиков доступна в информации о курорте. Атрибуция соответствует фактическому слою.

Фактическая облачная политика: restricted, enforced, observations_current=true, только preset package_managers. Хосты тайлов не разрешены. Однократный запрос через штатный HTTPS proxy к `a.tile.opentopomap.org` вернул **CONNECT 403 от Envoy**, до TLS/HTTP провайдера. Это блок на уровне среды, а не ошибка GPS, авторизации или доказанный отказ OpenTopoMap. Обходов политики, fake tiles, копирования стороннего рельефа и TLS-исключений нет.

**Скриншота с настоящей работающей топографической подложкой в этой среде нет. Критерий рельефа здесь не подтверждён.** Проверить его можно на Windows с разрешённым доступом к `a.tile.opentopomap.org`, `b.tile.opentopomap.org`, `c.tile.opentopomap.org`, `tile.openstreetmap.org`, либо после поддерживаемого обновления облачной политики. Браузерный тест с mocked 1px PNG проверяет только lifecycle резерва, не качество или доступность настоящих тайлов. Нет предзагрузки/массового скачивания/серверного tile proxy; штатные лицензии и ограничения публичных сервисов сохраняются.

## Аналитика фрирайда

Это расширение **того же `analyze()` GPS Engine 2.0**, не второй конкурирующий анализатор. Модуль `shared/terrain.ts` читает уже отфильтрованные points/edges, их descent/ascent/stop/gaps, `matchPiste` и `matchLift`. Worker, серверное сохранение и карта используют результат одного анализа.

Состояния каждого ребра: `piste`, `off_piste`, `lift`, `unknown`. У фрирайда нет «подтверждённой безопасности»: все `off_piste` здесь **probable**. Неполная карта может не содержать настоящую подготовленную трассу, поэтому формулировка в карточке — «Вне известных трасс — не подтверждено».

Для вероятного внетрассового движения нужны одновременно:

- Существующая карта и нахождение в её фактическом bbox.
- Уже распознанный спуск, валидные GPS-точки с горизонтальной точностью ≤20 м и без разрывов.
- Измеренная нисходящая тенденция: минимум 4 точки за локальное окно до 25 секунд, известная точность высоты ≤20 м, падение больше max(8 м, удвоенная худшая точность высоты).
- Расстояние до известных осевых линий больше max(40 м, 2×GPS accuracy +15 м); оба конца ребра должны находиться вне этого буфера.
- Непрерывно минимум 30 секунд и 100 м. Одиночный выброс не подходит. После подтверждения блока его начальные кандидаты помечаются ретроспективно.
- Возврат на трассу подтверждается совпадением в течение 10 секунд / 30 м; короткая неоднозначность остаётся unknown, а не достоверным фрирайдом.

При stop/ascent, плохой точности, недостоверной высоте, потере сигнала, выходе за карту и движении быстрее 25 м/с — unknown. Подтверждённый `matchLift` — lift. Неразмеченный замкнутый контур не используется как ось трассы; внутри него без подтверждённых площадных тегов — unknown. `piste:difficulty=freeride` или явный `piste:grooming=backcountry` учитывается как размеченный внетрассовый маршрут, но прохождение по GPS всё равно вероятное. По одному GPS невозможно гарантированно различить транспорт и катание; пороги исключают явные быстрые переезды, а не доказывают вид спорта.

Личный трек отдельный от OSM: фиолетовая линия — трассовый участок, пурпурные точки — вероятный фрирайд, серый штрих — unknown. Касание открывает карточку с дистанцией, временем, средней скоростью, достоверным перепадом (либо отсутствием данных) и уверенностью. В подробностях записи: дистанция по трассам, вероятный фрирайд/время/число участков, доля неизвестной дистанции. Unknown не включается в фрирайд.

Версия terrain-анализа и source IDs сохраняются в существующем JSON анализа сессии. Схема SQLite и user_version не меняются, старые записи читаются, повторный анализ детерминирован. Старая запись без сохранённой карты не получает выдуманную привязку задним числом. Исходные GPS не модифицируются этим расширением; существующая фильтрация GPS Engine остаётся прежней. Для воспроизводимости будущего повторного анализа нужен тот же неизменяемый пакет карты.

## Проверка и скриншоты

Всё выполнялось в `artifacts/map-design/map-data`, сервер Playwright порт 3099, SQLite `:memory:`. Пользовательская SQLite, рабочие `.env`, map-data, Tailscale, Telegram-авторизация, загрузчики и launcher не менялись. Тест SQLite reopen использует отдельный временный файл и удаляет только его.

- TypeScript и production build проходят. Модульные тесты: **95 проходят**. **19 браузерных сценариев проходят, 1 тест настоящего рельефа явно пропущен** из-за CONNECT 403; пропуск не считается успехом.
- Геометрия: обратные дубли, частичное коллинеарное наложение, конфликт сложности, пересечения, соседние линии, кольца, area=no, непрерывность цепочек и сохранение provenance relations.
- GPS: трасса, внетрассовый спуск, переход туда/обратно, шум, параллельные трассы, выброс, gap, остановка, подъём/канатка, отсутствие карты/высоты, неоднозначные контуры, быстрый транспортоподобный трек, повторный анализ и SQLite reopen.
- Браузер: 375/390/430, настоящий Домбай, одна и та же позиция до/после, постоянное число Canvas после zoom, реальное касание тонкой трассы и личного сегмента, статистика, панели, ограниченный fallback на эмулированных ответах.
- Строгий тест настоящего рельефа явно пропущен при `SLOPEMATE_MAP_OFFLINE=1` из-за подтверждённого CONNECT 403. Пропуск не считается успехом.

### Воспроизведение

```sh
node --import tsx scripts/audit-ski-geometry.ts artifacts/map-design/map-data/ru-dombay-b4cf6e169f805681.json
npm run check
npm run build
npm test
SLOPEMATE_TEST_MAPS="$PWD/artifacts/map-design/map-data" SLOPEMATE_MAP_OFFLINE=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

Для настоящего рельефа убрать OFFLINE и выполнить `dombay-real.spec.ts` в разрешённой сети. На Windows PowerShell переменные задаются через `$env:SLOPEMATE_TEST_MAPS=...`; локальная база приложения при этом не используется. Физический iPhone/Telegram, читаемость поверх настоящих тайлов и реальная GPS-запись в горах требуют отдельной ручной проверки. Для спорных контуров и двух кандидатов нужна исходная OSM-разметка: текущий пакет не позволяет честно завершить их семантическую проверку.
