# Аудит SlopeMate — 5 ноября 2026

Аудит выполнен от актуального main (merge PR #2). Пользовательские .env, SQLite и функциональные экраны не заменялись.

## Подтверждённые дефекты

1. **SOCKS socket idle 10 секунд против polling 25 секунд.** Установленный socks-proxy-agent 10.1.0 передаёт timeout в SOCKS handshake, затем вызывает socket.setTimeout(timeout) и уничтожает request/socket по timeout. Это потенциально порождает ECONNRESET на корректном молча ожидающем getUpdates. Регрессионный тест на локальном TLS+SOCKS воспроизводит прежний сбой в уменьшенном масштабе; исправленный агент дожидается ответа. TLS-проверка сохранена, недоверенный сертификат отклоняется. Это доказательство дефекта клиента, не полного поведения сети Karing.
2. **Остановка recovery после шести ошибок.** maxFailures=6 заканчивал runtime, требуя ручного перезапуска. Теперь transient ошибки восстанавливаются с ограниченной частотой, jitter и cooldown. Конфигурационные/программные ошибки не скрываются retry. Успех polling сбрасывает счётчик; последовательные ошибки и времена доступны оператору.
3. **Quick Tunnel был единственным полным сценарием 04_TELEGRAM.** Теперь по умолчанию fixed external endpoint; на VPS Windows только мониторит и не запускает вторую копию. Quick Tunnel явно тестовый. Бесплатный часовой Pinggy не является production-архитектурой.
4. **Нет подтверждения принадлежности публичного origin.** ok=true мог возвращать старый/другой сервер. Добавлена постоянная deployment identity и независимые проверки endpoint и Telegram-меню. ID не секрет и не заменяет авторизацию.
5. **Вся техническая диагностика была публичной.** Теперь сводка публична, подробные времена/errors/recovery закрыты bearer DIAGNOSTICS_TOKEN. Секреты, initData, координаты и request payload не логируются.
6. **Ошибка SQLite могла выглядеть как 401.** ensureUser находился в одном try/catch с проверкой initData. Ошибка БД теперь идёт в серверный error handler (500), а не выдаётся за плохую подпись Telegram.
7. **HTML tunnel-ошибка и JSON API не различались на клиенте.** Добавлен тип ошибки для авторизации, транспорта, gateway, протокола и сервера. В production ответ без initData больше не советует включать DEV_AUTH.
8. **Защита от дубликатов была только на уровне launcher/порта.** Добавлен host-local lock по hash токена с nonce и консервативной обработкой PID. Другие компьютеры всё ещё координируются правилом одного production poller и Telegram 409; распределённая блокировка не заявляется.

## Проверено и сохранено

HMAC initData, срок действия 1 час и запрет production dev-auth не ослаблены. API владельца сессии и приватность GPS сохранены. SQLite остаётся одной прежней базой с WAL/foreign keys; схема/сессии/профили/анализ треков не менялись. Сборка сохраняет backend + frontend на одном origin. Caddy передаёт HTTPS на loopback с TRUST_PROXY=1 для одного доверенного hop, без публикации 3001. systemd обеспечивает постоянный процесс и диск.

Локальный GPS-черновик зависит от HTTPS origin. Изменение адреса временного туннеля означает другое хранилище WebView — это ограничение платформы, не исчезновение SQLite. До миграции закончите синхронизацию на старом адресе. Авторизация после часа требует переоткрытия Mini App, с восстановлением черновика на том же origin.

## Гипотезы и непроверенные внешние причины

- Karing FakeIP/TUN, TLS EOF, сетевой reset или политика провайдера могут дополнительно разрывать соединение. Точная причина всех ECONNRESET на машине пользователя не доказана облачным аудитом.
- Регистрация cloudflared не доказывает доступность публичного приложения. 1033 относится к connector, 502 — к получению origin response; конкретные причины прежних логов без синхронных наблюдений PID/health неизвестны.
- ngrok ERR_NGROK_9040 — подтверждённый пользователем отказ сервиса по IP, не исправляемый code retry. Срок бесплатного Pinggy из наблюдений пользователя неприемлем для постоянного адреса.
- Текущие коммерческие лимиты/бесплатные условия Cloudflare/Tailscale/Pinggy не проверены: официальные страницы вернули proxy 403. Поэтому выбран provider-neutral VPS с доменом, без обещаний бесплатного SLA.
- Физический iPhone, Windows 10 BAT/CIM/taskkill, пользовательский Karing, реальный VPS/DNS/сертификат и 90-минутная приёмка здесь недоступны. Mock/TLS fixture не объявляются реальной Telegram-проверкой.
