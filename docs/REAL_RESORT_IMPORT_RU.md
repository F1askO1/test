# Реальные карты: Домбай сначала, затем расширение

Дата проверки: 5 ноября 2026. База 269dec0, ветка fix/resort-data-pipeline. **Подтверждённо работающая карта Домбая пока не получена.** Единственный живой источник был остановлен облачным HTTPS proxy: CONNECT 403 до отправки запроса Overpass. Статус остальных контрольных курортов — not-attempted, а не «проверено, данных нет». Фактический отчёт: [real-data-control-report.json](real-data-control-report.json).

## Что исправлено

Раньше fetch-ski.mjs выполнял один тяжёлый запрос на всю Россию. Теперь единица подготовки — курорт из map-sources/resorts.json. По умолчанию **только Домбай**. На него приходится четыре небольших запроса: winter_sports/site=piste, downhill-ways и члены piste-relations, линии aerialway, реальные station-nodes. Каждый запрос ограничен 45 с серверного исполнения, 60 с HTTP и 32 MiB. Никакого запроса area Russia при обычном запуске.

Каждая часть записывается отдельно и атомарно в artifacts/maps/raw/<id> с SHA-256, fingerprint запроса/endpoint и временем. Повтор использует только проверенные части; испорченная или относящаяся к другому запросу часть загружается заново. Пустая корректная часть тоже сохраняется (например, нет stations). Итоговый prepared snapshot возникает только после успеха всех четырёх частей. Контрольный batch отмечает установленный, ошибочный и ещё не запрошенный курорт отдельно.

Сетевые ошибки, 429 и временные 5xx: до 3 попыток, exponential backoff/jitter, Retry-After ограничен 30 с. 400/401/403 не повторяются. Вложенный Undici «Proxy response (403)» тоже распознаётся; при политическом запрете batch прекращается, альтернативные домены для обхода не перебираются. Перед запросами выдерживается пауза. Отдельная PID-блокировка исключает второй одновременный fetch того же курорта. После нормальной ошибки lock снимается; lock погибшего процесса того же ПК восстанавливается без убийства чужих процессов.

Сохранённый кэш сам по себе не обновляется ежедневно. Для свежей повторной выгрузки предусмотрен --refresh и пункт 7 Windows-меню. При конфликте изменившегося объекта в разных частях нужна именно свежая подготовка, а не бесконечное использование старых частей.

## Принадлежность и качество

Отсутствие landuse=winter_sports больше не блокирует именованный импорт. --resort dombay выбирает заранее указанное **поисковое окно**, а не создаёт поддельную OSM-площадку или геометрию трассы. Имя и регион — операторская настройка; линии, станции, сложность и source ID приходят из источника. Поисковые окна не проверены как официальные границы. Особенно у Розы Хутор нужна ручная проверка соседних комплексов. Не выводим ложное «официально принадлежит»; UI и quality report отмечают search-window.

Нормализатор не соединяет линию через некорректную/пропущенную координату: такая линия исключается с записью в rejections. Проверяются диапазоны, ненулевая длина, подозрительно длинные сегменты (>3 км требуют проверки), длина линии >40 км, повтор ID, совпадающая геометрия и попадание ≥80% вершин в выбранную область. Явный конфликт piste:resort с выбранным названием исключается. Сложность берётся из piste:difficulty (включая novice), не вычисляется по уклону. Если несколько piste-relations противоречат по сложности, не выбирается произвольная категория. Недостающие station/верх/низ не рисуются на концах.

Перед установкой нужны минимум одна пригодная downhill-линия и один подъёмник, согласованные counters и валидная схема. Это нижняя граница пригодности, **не доказательство полноты курорта**. Неизвестная сложность допустима с предупреждением; нулевая классификация не является подтверждением цветной карты. Отчёт coverage.json содержит actual counts, classification share, ошибки/предупреждения и source hash. Число линий — геометрические участки, не гарантированное число целых официальных трасс.

Каталог обновляется атомарно и **сливается по ID курорта**, не стирает уже подготовленные другие курорты. Старые файлы/предыдущий индекс не удаляются. Ошибка загрузки/качества не заменяет каталог пустым. SQLite, .env, личные треки, initData, Tailscale и GPS Engine не участвуют в установке карт.

## Windows: подготовить и перенести без ручного кода

1. Обновите ZIP с сохранением .env, data и собственной наполненной map-data. Выполните 01_INSTALL.bat при необходимости.
2. На ПК с **разрешённым** доступом к источникам откройте **09_UPDATE_MAPS.bat**.
3. Пункт 1 → Домбай. Дождитесь сообщения об установке и отчёта качества. При ошибке просто повторите: готовые части сохраняются.
4. После получения реального Домбая пункт 2 подготовит пять контрольных курортов последовательно: Домбай, Архыз, Роза Хутор, Эльбрус, Шерегеш. Если первый Домбай не прошёл подготовку/качество, расширение останавливается.
5. Пункт 4 создаёт **map-exports/\*.slopemap**. Внутри только проверенные геоданные и атрибуция; нет SQLite, .env, node_modules, GPS или секретов.
6. Перенесите .slopemap обычным USB/файлом на рабочий ПК. Пункт 5 открывает выбор файла, показывает имена/counts/источники, затем просит явное «ДА» для установки. На ПК-получателе доступ к Overpass не требуется.
7. Переоткройте Mini App, выберите Домбай. API по-прежнему требует Telegram-авторизацию; DEV_AUTH в публичном режиме не включайте.

Пакет gzip ограничен 32 MiB сжатым / 64 MiB распакованным; каждый набор ≤12 MiB. SHA проверяет повреждение при переносе, **не удостоверяет отправителя и не доказывает достоверность карты**. Устанавливайте только от доверенного подготовителя. Никакие архивные пути не извлекаются: записываются только валидированные bundles с безопасными ID. Пользовательская БД и конфигурация не копируются/не перезаписываются.

Команды для разработчика:

```cmd
npm run maps:prepare -- --resort dombay
npm run maps:prepare -- --control
npm run maps:prepare -- --resort dombay --refresh
npm run maps:fetch -- --region caucasus
npm run maps:import -- artifacts/maps/prepared/dombay/overpass.json --resort dombay
npm run maps:package -- export C:\Transfer\dombay.slopemap
npm run maps:package -- inspect C:\Transfer\dombay.slopemap
npm run maps:package -- import C:\Transfer\dombay.slopemap
```

Расширение на новые курорты/регионы — отдельные проверяемые записи manifest (с --manifest для fetch/import); это не автоматическое обещание всей России. До подтверждения Домбая национальная загрузка не запускается.

## Альтернатива 1 — OpenSkiData

Изучена опубликованная схема **openskidata-format 16.0.0** (Run, Lift, Source, skiAreas), не угадан произвольный GeoJSON. Источник формата: https://www.npmjs.com/package/openskidata-format и https://github.com/russellporter/openskidata-processor . Адаптер принимает ограниченный локальный FeatureCollection, properties.type=run с uses=downhill и properties.type=lift (реальные lowercase-значения enum v16), LineString/MultiLineString, duration в секундах, novice и неизвестную сложность, исходные OSM URLs. Объекты другого явно указанного skiArea не присваиваются выбранному курорту. Полигон трассы **не превращается в нарисованную центральную линию**, неподдерживаемые геометрии пропускаются. Не-OSM geometry без исходного OSM ID не принимается.

В меню пункт 3: выбрать локальный GeoJSON и курорт. Или:

```cmd
npm run maps:import -- C:\Downloads\dombay-openskidata.geojson --resort dombay
```

Прямой сайт https://openskidata.org в этой среде тоже запрещён policy; URL актуальной выгрузки/условия выдачи не были проверены. Адаптер протестирован на синтетическом fixture **структуры опубликованной схемы**, не на загруженном реальном Домбае. Загрузка/потоковое разбиение мирового GeoJSON не автоматизированы: вход до 64 MiB должен быть выделенным набором. Не выдаём это за полностью проверенную замену Overpass; это дополнительный локальный формат без вызова Overpass.

## Альтернатива 2 — региональный OSM

https://download.geofabrik.de/russia.html предоставляет региональные OSM-выгрузки, с лицензией ODbL. Выберите подходящий регион в разрешённой сети. Прямое получение файла и актуальные размеры не проверены здесь из-за policy; скачивать гигабайты при запуске Mini App не нужно.

На подготовительном ПК отдельно установите **osmium-tool** (https://osmcode.org/osmium-tool/); это необязательный инструмент подготовки, не сервер и не npm-зависимость приложения. На Linux/WSL он доступен пакетным менеджером, на Mac — Homebrew. Наличие native Windows-бинарника и его версию необходимо проверить отдельно; можно указать OSMIUM_PATH. Меню пункт 6 запускает extract с complete_ways, отбор нужных тегов и конвертацию в OSM XML. Исходный PBF не изменяется. Процесс может требовать заметную память и время; он вынесен из обычного запуска. Osmium здесь не установлен и команды не проверены на реальном PBF.

```cmd
npm run maps:extract -- C:\Downloads\region.osm.pbf dombay
```

После успешного извлечения путь к resort.osm напечатается; меню пункт 3 импортирует его для Домбая. OSM XML преобразуется с сохранением node references/route relations. Missing-node геометрия отвергается; DTD/ENTITY и чрезмерная вложенность запрещены. Этот путь **не использует Overpass**. Ограниченный OSM XML можно получить другим разрешённым GIS-инструментом и импортировать напрямую.

- npm run check/build: успешно.
